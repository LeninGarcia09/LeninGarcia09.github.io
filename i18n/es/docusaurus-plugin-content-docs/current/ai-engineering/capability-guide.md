# Decide el siguiente paso con evidencia, no etiquetas

Esta guía evalúa progreso en capacidades transferibles. No es auditoría de empleadores, rúbrica de contratación ni declaración de preparación profesional.

Usa cuatro estados: **demostrado**, **necesita práctica**, **no evaluado** y **fuera del alcance actual**. “Demostrado” significa ejecutar y explicar el artefacto, no reconocer vocabulario.

## Mapa práctico

| Capacidad | Evidencia A/B | C añade | Práctica de entrega opcional |
| --- | --- | --- | --- |
| Software | Flujo archivo/API probado, SQL, entorno reproducible y CI | Contratos entrenamiento/servicio y consistencia de características | Fallos async, aislamiento y solicitudes recuperables |
| Datos | Procedencia, esquema, duplicados y actualizaciones | Ingesta incremental, backfill, evolución, calidad y linaje | Contratos de integración y filtros de acceso |
| Criterio ML | Referencias, divisiones limpias, métricas y errores | Entrenamiento, incertidumbre, selección, artefactos y experimentos | Controles de evaluación para entrega y diagnóstico |
| Respuestas con fuentes | Etiquetas de recuperación, citas, abstención y prueba reservada | Comparación recuperación/adaptación en misma tarea | Aislamiento de estado y evaluación al recuperar |
| Flujos acotados | Solo lectura, argumentos y presupuestos | Solo si aportan al proyecto | Persistencia, reinicio, contrato de protocolo y aprobación |
| Operación | Entrega de pruebas, monitoreo y rollback | Recuperación entrenamiento-servicio; deriva frente a bug de datos | Carga, configuración reproducible y ensayo de incidentes |
| Explicación | Casos reproducibles y límites honestos | Decisiones conectadas de datos/entrenamiento/servicio | Revisión de diseño, guía de recuperación y mejora con feedback |

## Autoevaluación de 30 minutos

1. Ejecuta el proyecto con sus comandos documentados.
2. Cambia una entrada para provocar fallo; predice y explica el comportamiento.
3. Reproduce evaluación reservada sin reajustar.
4. Identifica límite de datos/permisos y una limitación importante.
5. Si hay revisor, pídele repetir un paso; registra solo comentarios recibidos.

Por capacidad: **artefacto → comando/prueba → resultado → brecha → próximo ejercicio**. Elige una brecha, no otra lista de frameworks.
